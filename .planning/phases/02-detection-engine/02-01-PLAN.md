Create `internal/detection/window.go` in package `detection` with the sliding window helper:

```go
package detection

import "time"

type slidingWindow struct {
    timestamps []time.Time
    head       int
    count      int
}

func newSlidingWindow(capacity int) *slidingWindow {
    return &slidingWindow{timestamps: make([]time.Time, capacity)}
}

func (w *slidingWindow) Add(t time.Time) {
    w.timestamps[w.head%len(w.timestamps)] = t
    w.head++
    if w.count < len(w.timestamps) {
        w.count++
    }
}

func (w *slidingWindow) CountWithin(d time.Duration) int {
    cutoff := time.Now().Add(-d)
    n := 0
    for i := 0; i < w.count; i++ {
        idx := (w.head - 1 - i + len(w.timestamps)) % len(w.timestamps)
        if w.timestamps[idx].After(cutoff) {
            n++
        }
    }
    return n
}

func (w *slidingWindow) Evict(olderThan time.Duration) {
    cutoff := time.Now().Add(-olderThan)
    newTs := w.timestamps[:0]
    for i := 0; i < w.count; i++ {
        idx := (w.head - w.count + i + len(w.timestamps)) % len(w.timestamps)
        if w.timestamps[idx].After(cutoff) {
            newTs = append(newTs, w.timestamps[idx])
        }
    }
    copy(w.timestamps, newTs)
    w.count = len(newTs)
    w.head = w.count
}
```

IMPORTANT: Do NOT use `container/ring` -- plain slice with head/count is simpler and avoids interface{} casts. Do NOT add a `break` optimization in CountWithin -- out-of-order Kafka delivery means timestamps are not guaranteed monotonic.

Create `internal/detection/engine.go` in package `detection`:

1. Define `cooldownKey` struct: `{ ruleID string; service string }`

2. Define `DetectorEngine` struct with fields:
   - `detectors []domain.Detector` -- registered rule implementations
   - `cooldowns map[cooldownKey]time.Time` -- per-(rule,service) last-fire time (DETECT-08, wired in Plan 02-04)
   - `cooldownDur time.Duration` -- from `cfg.CooldownDuration`
   - `warmupUntil time.Time` -- `time.Now().Add(warmupMultiplier * maxWindow)` where maxWindow is the longest configured window across all rules
   - `logger *zap.Logger`
   - `out chan domain.Anomaly` -- buffered capacity 256
   - `evictStop chan struct{}` -- signals eviction goroutine to stop

3. `NewDetectorEngine(detectors []domain.Detector, cfg DetectionConfig, logger *zap.Logger) *DetectorEngine`:
   - Compute `maxWindow` by iterating cfg.Rules fields to find the largest window/silence_after duration
   - Create a helper func `maxWindowDuration(cfg DetectionConfig) time.Duration` that returns the max of all rule window durations and ServiceSilence.SilenceAfter
   - Set `warmupUntil = time.Now().Add(time.Duration(cfg.WarmupMultiplier) * maxWindow)` -- default WarmupMultiplier=2 per Pitfall A1
   - Initialize cooldowns map, out channel (cap 256), evictStop channel
   - Start `go e.evictLoop(cfg.EvictionInterval)` background goroutine
   - Return engine pointer

4. `Evaluate(entry domain.LogEntry)` method:
   - If `time.Now().Before(e.warmupUntil)` return immediately (warm-up suppression)
   - Range over `e.detectors`, call `d.Evaluate(entry)`
   - If fired: build `cooldownKey{ruleID: anomaly.RuleID, service: anomaly.Service}`
   - Check cooldown: if `last, ok := e.cooldowns[key]; ok && time.Since(last) < e.cooldownDur` then continue (suppress)
   - Otherwise: set `e.cooldowns[key] = time.Now()`, increment `metrics.AnomaliesDetectedTotal.WithLabelValues(anomaly.RuleID).Inc()`
   - Send anomaly to `e.out` via non-blocking select with default case that logs a warning via zap

5. `Anomalies() <-chan domain.Anomaly` -- returns read-only channel

6. `Stop()` -- closes `e.evictStop` channel

7. `evictLoop(interval time.Duration)`:
   - `time.NewTicker(interval)`, defer Stop
   - Select on ticker.C: call `d.Reset()` on each detector (Reset evicts stale entries, NOT full clear -- per Pitfall A2)
   - Also evict stale cooldown entries: delete from `e.cooldowns` where `time.Since(last) > e.cooldownDur * 2`
   - Select on `e.evictStop`: return

Import paths: `github.com/log-analytics/server/internal/domain`, `github.com/log-analytics/server/internal/metrics`, `go.uber.org/zap`, `time`.

IMPORTANT: Do NOT use sync.Mutex on the engine -- single-goroutine ownership means Evaluate is called from one goroutine only (the pipeline worker). The evictLoop runs in a separate goroutine but only calls d.Reset() which each rule handles safely. If this creates a race condition, it will be addressed in Plan 02-04 with channel-based coordination. For now, document the single-goroutine-caller contract in a comment on Evaluate.
