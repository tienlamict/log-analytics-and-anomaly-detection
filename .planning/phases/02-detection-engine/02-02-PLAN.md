- `cfg ErrorRateConfig`
- `capacity int` -- default 10000 (max events in buffer)

- Initialize windows map, store cfg, set capacity to 10000

`Name() string` returns `"error_rate_spike"`

`Evaluate(entry domain.LogEntry) (domain.Anomaly, bool)`:
- If `entry.Level != "error"` return zero Anomaly and false
- Get or create `slidingWindow` for `entry.Service`
- Call `w.Add(entry.Timestamp)` (use entry timestamp, NOT time.Now() -- per research anti-pattern note)
- Count = `w.CountWithin(r.cfg.Window)`
- If count >= `r.cfg.Threshold`: return Anomaly with ID=uuid.NewString(), RuleID=r.Name(), Severity=r.cfg.Severity, Service=entry.Service, Description=fmt.Sprintf("error rate spike: %d errors in %s for service %s", count, r.cfg.Window, entry.Service), Evidence=[]domain.LogEntry{entry}, DetectedAt=time.Now()
- Else return false

`Reset()`: For each service window, call `w.Evict(r.cfg.Window)` -- evict entries older than window duration. Do NOT clear the entire map (Pitfall A2).

**LatencyThresholdRule** (`internal/detection/latency.go`):

Needs a custom window that tracks both total requests and breach count. Define a local struct:

```go
type latencyEntry struct {
    timestamp time.Time
    breached  bool
}

type latencyWindow struct {
    entries  []latencyEntry
    head     int
    count    int
}
```

With methods: `Add(t time.Time, breached bool)`, `StatsWithin(d time.Duration) (total int, breaches int)`, `Evict(olderThan time.Duration)`.

Struct fields:
- `windows map[string]*latencyWindow` -- keyed by service
- `cfg LatencyConfig`
- `capacity int` -- 10000

Constructor: `NewLatencyThresholdRule(cfg LatencyConfig) *LatencyThresholdRule`

`Name()` returns `"latency_threshold_breach"`

`Evaluate(entry domain.LogEntry) (domain.Anomaly, bool)`:
- Extract duration_ms from `entry.Fields`. Check BOTH `"duration_ms"` and `"latency_ms"` field names.
- Type-assert: try `float64` first (JSON default), then try numeric string conversion. If neither works, return false (skip entry).
- Determine if breached: `durationMs >= float64(r.cfg.ThresholdMs)`
- Get or create latencyWindow for entry.Service
- Add entry with breach flag
- Get stats: `total, breaches := w.StatsWithin(r.cfg.Window)`
- If total == 0 return false
- breachRate = (breaches * 100) / total
- If breachRate >= r.cfg.BreachRatePercent: return Anomaly with Description=fmt.Sprintf("latency breach: %d%% of %d requests exceeded %dms in %s", breachRate, total, r.cfg.ThresholdMs, r.cfg.Window)
- Else return false

`Reset()`: evict entries older than window for each service.

Create `internal/detection/repeated_failure.go` in package `detection`:

1. Define package-level compiled regex for fingerprinting:
```go
var fingerprintNoise = regexp.MustCompile(`\b[\da-fA-F]{4,}\b|\b\d+\b`)
```
This strips: hex strings 4+ chars (UUIDs, hashes, addresses), decimal numbers. Result: stable fingerprint for same error class.

2. Define `fingerprint(msg string) string` function:
   - `return fingerprintNoise.ReplaceAllLiteralString(strings.ToLower(msg), "X")`

3. `RepeatedFailureRule` struct:
   - `windows map[string]*slidingWindow` -- keyed by `service + "|" + fingerprint(message)`
   - `cfg RepeatedFailureConfig`
   - `capacity int` -- 10000

4. Constructor: `NewRepeatedFailureRule(cfg RepeatedFailureConfig) *RepeatedFailureRule`

5. `Name()` returns `"repeated_failure"`

6. `Evaluate(entry domain.LogEntry) (domain.Anomaly, bool)`:
   - Only consider error-level entries: if `entry.Level != "error"` return false
   - Compute fp = `fingerprint(entry.Message)`
   - Build composite key: `key := entry.Service + "|" + fp`
   - Get or create slidingWindow for key
   - `w.Add(entry.Timestamp)`
   - count = `w.CountWithin(r.cfg.Window)`
   - If count >= r.cfg.Threshold: return Anomaly with Description=fmt.Sprintf("repeated failure: fingerprint %q seen %d times in %s for service %s", fp, count, r.cfg.Window, entry.Service)
   - Else return false

7. `Reset()`: for each key's window, call `w.Evict(r.cfg.Window)`. Delete map entries where window count is 0 after eviction (prevent unbounded map growth for transient fingerprints).

IMPORTANT: The composite key includes both service and fingerprint so the same error from different services is tracked independently.
